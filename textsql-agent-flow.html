两套闭环，分开画

词以 CONTEXT.md 为准。B3 提示词以 textsql-rewrite-prompt.md 为准。主 Agent 按 ReAct（Reason + Act）转圈。不是 React 前端。每一句用户话只进环 A 或环 B。

入口（只有一次分流）

用户说话 → 主 Agent 规划：不查库走左边环 A（不调查数工具）；要查库则调查数工具一次，内部跑右边环 B。先澄清再查：本句环 A，下一句再调查数工具。联网搜索已设计、默认关闭。

环 A · 正常对话

不查库。联网搜索已设计、默认关闭。不调用小模型、Vanna RAG、查库大模型

A1 用户说话
▼
A2 主 Agent
规划：不查数 · 会话记忆 · 大模型说话
▼
A3 回复用户
↑ 回到 A1，等下一句
环 A 上下文
[系统：对人说话，精确数只来自查库回填] [会话记忆] [用户本轮这句话] → 回复用户 联网搜索：已设计，默认不挂载

环 B · 查数

主 Agent 调查数工具一次；内部：小模型改写 → RAG 一次 → 查库对话

B1 用户说话
▼
B2 主 Agent
规划：要查数 · 写出当前问题 · 调查数工具一次
▼
B3 小模型改写
改写问题 + 需求说明
▼ 改写问题进 Vanna RAG
B4 Vanna 内 RAG（三字段对照一次）
▼ 新 RAG = 全新查库对话
B5 查库对话
只读跑 SQL · 最多 5 次 · 超时 30 秒 · 0 行也停
▼ 回填
B6 回复用户
查库成功才成对写 SQL+摘要
↑ 回到 B1，等下一句
查数工具（默认开启）
名称：查数工具 入：当前问题 出：有行 → SQL+截断结果；0 行 → 没查到；失败用尽 → 最后SQL+报错 副作用：成功则成对覆盖上次 SQL+需求说明 内部：B3→B6，主 Agent 不可插步 同一句最多调 1 次
B3 小模型
[固定前缀] [上次 SQL] ← 没有就空 [查询摘要] ← 指标/时间/过滤/口径；没有就空 [当前问题] → 改写问题 + 需求说明 全文：textsql-rewrite-prompt.md
B5 查库对话 / B6 落盘
只给只读查库工具。报错或超时：对话内改 SQL 再跑。 有行或 0 行：查库成功，离开 B5，丢掉这次对话。 0 行：对人说没查到，仍覆盖两个槽。 5 次用尽仍失败：两槽不动，本轮摘要扔掉。

Vanna 连库 · 框架内 RAG（不外挂）

检索只用 Vanna 自带 RAG。query 是改写问题。查库的是大模型，只调只读工具。

Vanna 配置 ├── 框架内 RAG（DDL / 文档 / 问题-SQL） ├── 查库大模型（查库对话；不再检索第二遍） └── 只读数据库连接 + 只读查库工具（最多 5 次，超时 30 秒）
改写问题 ├─ 对照 DDL/表结构 → 相关表、字段 ├─ 对照 文档/口径 → 指标含义、同义词 └─ 对照 问题-SQL 样例 → 相似问法的 SQL → 三路命中 → 交给这一次查库对话

前提：ReAct 思考模式（为什么是环）

不是 React 前端。是 Reason + Act：思考 → 行动 → 观察 → 再思考。

观察：用户这句话 / 查库结果、没查到、或报错（联网搜索开启后才有搜索结果） 思考：主 Agent 规划 —— 聊天还是查数？写出当前问题 行动：环 A 直接说话；要查数则调查数工具一次（内部跑环 B） 再观察：查数工具回填 → 对人说 → 等下一句 查数工具内部改 SQL 再跑，是 B5 小环，不是主 Agent 再调一次查数工具。联网搜索已设计、默认关闭。
