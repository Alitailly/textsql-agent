主 Agent 是一个决策循环

词以 CONTEXT.md 为准。B3 提示词以 textsql-rewrite-prompt.md 为准。主 Agent 按 ReAct（Reason + Act）转圈——不是 React 前端，也不是「一句只规划一次」的二选一开关。

起点：每一圈只问一句话

「手上这些材料，够不够回答用户？」 够了就说话、本轮结束；不够就调一个工具，拿到回填，再问一遍。

主 Agent 不写 SQL、不查库，也不参与改写问题。它交给查数工具的只有「当前问题」这一句；改写完全由工具内部的小模型负责。

循环本体

一轮（用户的一句话）里可以转好几圈，中途可以换工具

思考够不够回答？
行动说话 / 查数 / 搜索
观察看工具回填
再思考还缺什么？
说话本轮结束
└──────────────── 不够就调工具，回到「思考」 ────────────────┘
调查数工具默认开启每轮最多 1 次 · 内部跑环 B
联网搜索默认关闭拿到库内容后按需 · 每轮最多 3 次

查数工具（默认开启）
名称：查数工具 入：当前问题 出：有行 → SQL+截断结果；0 行 → 没查到；失败用尽 → 最后SQL+报错 副作用：成功则成对覆盖上次 SQL+需求说明 内部：B3→B6，主 Agent 不可插步 同一句最多调 1 次
B3 小模型
[固定前缀] [上次 SQL] ← 没有就空 [查询摘要] ← 没有就空 [当前问题] → 改写问题 + 需求说明 全文：textsql-rewrite-prompt.md
B5 查库对话 / B6 落盘
只给只读查库工具。报错或超时：对话内改 SQL 再跑。 有行或 0 行：查库成功，离开 B5，丢掉这次对话。 0 行：对人说没查到，仍覆盖两个槽。 5 次用尽仍失败：两槽不动，本轮摘要扔掉。

关键：联网搜索是主 Agent 的决定，不在环 B 内

它既不是环 A 的专利，也不是环 B 的一个环节。典型情形正是这个项目的价值主张所在。

主 Agent 调查数工具 → 拿到库里的确切事实（谁、多少粉、什么类目、哪个邮箱） ↓ 判断：光拿这些回复用户，不够 / 不对 ↓ 联网搜索，补充库外的时效性内容 ↓ 把「库里的锚点」和「网上的补充」合成一句回复
库给的是 不可幻觉的锚点 搜索给的是 时效性 主 Agent 给的是 合成 —— 三样缺一样，就跟通用网页版没区别
名称：联网搜索 调用方：仅主 Agent 开关：默认关闭，不挂载 入：一句搜索词 出（成功）：最多 5 条；每条 标题 / 网址 / 摘要（单条截到约 300 字） 出（失败）：错误原文；对人说明搜不到，不编网页内容 保险丝：每轮最多 3 次；单次超时 15 秒，算一次失败并计入这 3 次 回填进主 Agent 会话，不写进上次 SQL / 查询摘要；网页数字不当成库里的数

Vanna 连库 · 框架内 RAG（不外挂）

检索只用 Vanna 自带 RAG。query 是改写问题。查库的是大模型，只调只读工具。

Vanna 配置 ├── 框架内 RAG（DDL / 文档 / 问题-SQL） ├── 查库大模型（查库对话；不再检索第二遍） └── 只读数据库连接 + 只读查库工具（最多 5 次，超时 30 秒）
改写问题 ├─ 对照 DDL/表结构 → 相关表、字段 ├─ 对照 文档/口径 → 指标含义、同义词 └─ 对照 问题-SQL 样例 → 相似问法的 SQL → 三路命中 → 交给这一次查库对话

ReAct 思考模式（为什么是循环）

不是 React 前端。是 Reason + Act：思考 → 行动 → 观察 → 再思考。

观察：用户这句话；工具回填 —— 查数结果、没查到、报错，或搜索结果 思考：主 Agent 自问 —— 现在够不够回答用户？还缺什么？ 行动：说话；或调查数工具一次；或联网搜索（默认关闭） 再观察：工具回填或用户下一句 → 再思考 三条路： 纯对话 观察用户 → 不用查库 → 说话 → 等下一句 查数 观察用户 → 要库里的锚点 → 写当前问题 → 调查数工具 → 观察回填 查完不够 观察回填 → 这些不足以回答 → 联网搜索 → 观察结果 → 合成回复 查数工具内部改 SQL 再跑，是 B5 小环，不是主 Agent 再调一次查数工具。
