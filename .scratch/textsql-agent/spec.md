## Problem Statement

我要用自然语言跟一个主 Agent 多轮问数。主 Agent 必须能聊天，也必须能查库，但不能自己写 SQL、不能自己连库。查数必须封装成主 Agent 的一个查数工具：传入当前问题，内部跑完环 B 再回填；一句最多调一次。联网搜索要先设计好工具契约，但默认关闭、先不挂到主 Agent 上，以后要再用时再开。查失败不能把上一轮已经查对的 SQL 和摘要丢掉。0 行要告诉我没查到，并且能拿这条空查询当下一轮续问的底座。网页上搜到的数字不能当成我库里的数。我不要槽位状态机，也不要再发明一套检索。

## Solution

每一句用户话，主 Agent 只规划一次：走环 A（对话，不调查数工具）或调查数工具一次（内部跑环 B 工作流）。查数工具默认开启：入参是当前问题，内部固定为小模型改写（同时产出四项查询摘要）→ Vanna RAG 一次检索 → 查库大模型在全新查库对话里只调只读查库工具；报错或超时则在该对话内改 SQL 再跑，有行或 0 行则停。查库成功（含 0 行）时程序把上次 SQL 和四项摘要成对覆盖；工具失败用尽则两槽不动。主 Agent 打乱不了工具内部顺序，也不能把 B3/B4/B5 拆成自己的多个工具。联网搜索工具已按契约设计，默认关闭、不挂载；开启前环 A 只说话。开启后仍只在环 A 可调，同一句不又搜网页又调查数工具。小模型无跨轮记忆。查库大模型的记忆只活在这一次查库对话里，新 RAG 或离开 B5 就丢掉。跨轮连续性放在主 Agent 的会话里：它把用户原话收成可独立理解的当前问题，交给查数工具，并用回填结果对人说话。

## User Stories

1. As a 业务用户, I want 用自然语言问库里的数, so that 我不用自己写 SQL。
2. As a 业务用户, I want 只聊天、不查数时得到普通对话回复, so that 问口径、问好不好查、打招呼不会误触发查库。
2a. As a 业务用户, I want 联网搜索默认关着, so that 现在的对话不会去外网。
2b. As a 业务用户, I want 以后打开联网搜索时主 Agent 能查公开口径或行业说明, so that 我不必自己去搜。
2c. As a 业务用户, I want 网页上搜到的数字不要被说成我库里的数, so that 公开资料和只读查询分得清。
2d. As a 业务用户, I want 联网搜索开启后「先搜含税口径，再查上个月销售额」仍拆成两句, so that 同一句不会又搜又查。
3. As a 业务用户, I want 主 Agent 在环 A 里不要编造库里的精确数字, so that 我不会把猜的数当成查询结果。
4. As a 业务用户, I want 「帮我查上个月销售额，但你先告诉我销售额口径」这一句先只得到口径解释, so that 同一句话不会既聊天又查数。
5. As a 业务用户, I want 上一句听完口径之后再说「查吧」才真正查数, so that 先澄清再查数拆成两轮。
6. As a 业务用户, I want 查数结果用人话告诉我, so that 我不必直接读 SQL 或原始表。
7. As a 业务用户, I want 在上一问基础上说「那按城市呢」仍能查, so that 我可以叠条件，不必每次重说完整问题。
8. As a 业务用户, I want 说「就按你说的第一个」时系统仍去查对的口径, so that 口语指代不会进小模型原样改写。
9. As a 业务用户, I want 看到的是查库得来的数而不是主 Agent 编的数, so that 我信任答句里的数字来自只读查询。
10. As a 业务用户, I want 查库失败时被告知失败原因而不是假数, so that 我知道这次没查成。
11. As a 业务用户, I want 这次 SQL 报错失败后，上一轮已经查对的口径还在, so that 我下一句「按城市拆」仍叠在上次成功查询上，而不是叠在失败 SQL 上。
12. As a 业务用户, I want 查到 0 行时被告知没查到, so that 我知道这次条件过严或没有数据。
13. As a 业务用户, I want 0 行之后说「别按城市了」仍能依据刚才那条空查询改写, so that 过严过滤也能当续问底座。
14. As a 业务用户, I want 0 行之后系统不要自己放宽条件再查一次, so that 要不要继续查由我说了算。
15. As a 业务用户, I want 系统绝不能用我的话去改库、删表、插数, so that 问数不会变成写库。
16. As a 业务用户, I want 一次查数不要跑到把服务拖死, so that 对话还能继续。
17. As a 业务用户, I want 首轮查数在没有上次 SQL、没有查询摘要时仍然能查出结果, so that 系统不是必须先有一次成功才能用。
18. As a 业务用户, I want 连续两轮都查数时，第二轮小模型能看到第一轮成功留下的上次 SQL 和查询摘要, so that 叠问有底座。
19. As a 业务用户, I want 环 A 之后下一轮再走环 B 时，仍能用对话里刚澄清的口径去查, so that 先聊后查不会丢上下文。
20. As a 业务用户, I want 重试过程不要把中间失败 SQL 一股脑说给我听（除非最终仍失败）, so that 成功时我只关心结果。
21. As a 主 Agent, I want 每一轮只在「不调查数工具」和「调查数工具一次」里选一次, so that 规划简单，不会在同一句里任意插内部步骤。
21a. As a 主 Agent, I want 查数工作流封装成一个查数工具, so that 我只传入当前问题、只看回填，不直接调小模型或查库大模型。
21b. As a 主 Agent, I want 查数工具默认就挂在我手上, so that 要查数时有且只有这一只手。
22. As a 主 Agent, I want 环 A 根本不调查数工具、不调用小模型、Vanna RAG、查库大模型, so that 闲聊没有查数副作用。
22a. As a 主 Agent, I want 联网搜索默认不出现在我的工具列表里, so that 关着的时候我调不到它。
22b. As a 主 Agent, I want 联网搜索开启后只在环 A 可调, so that 公开资料不必编。
22c. As a 主 Agent, I want 调查数工具的这一句不调用联网搜索, so that 查数管线不被网页结果搅进去。
22d. As a 主 Agent, I want 联网搜索开启后会话里记住搜索回填, so that 搜过的说明下一句还能用来写当前问题。
23. As a 主 Agent, I want 判定要查数时把用户原话收成一句可独立理解的当前问题再交给查数工具, so that 小模型不必看近几轮对话。
24. As a 主 Agent, I want 用户原话只留在我这边, so that 指代消解发生在规划者，而不是改写模型。
25. As a 主 Agent, I want 查数工具结束后看到 SQL、截断后的结果、没查到或报错, so that 我能用人话回复用户。
26. As a 主 Agent, I want 会话里记住用户原话、我说过的话和查数工具回填, so that 我能写出当前问题并接着上一句说话。
27. As a 主 Agent, I want 不把上次 SQL 和查询摘要当作我自己的记忆, so that 程序槽和小模型输入不会变成两份账。
28. As a 主 Agent, I want 规划判成环 A 时本轮绝不调查数工具, so that 「只有一次分流」有可观察的副作用边界。
29. As a 主 Agent, I want 同一句用户话里查数工具最多调一次, so that 看见 0 行或难看结果时不会在用户说话前再查一次。
30. As a 小模型, I want 每次只看到固定前缀、上次 SQL、查询摘要、当前问题, so that 我无记忆、不查库、不做规划。
31. As a 小模型, I want 上次 SQL 或查询摘要没有时槽位为空, so that 首轮查数仍然能改写。
32. As a 小模型, I want 一次输出改写问题和四项查询摘要, so that 程序能拿改写问题去检索，并把摘要留到成功后再落盘。
33. As a 小模型, I want 改写句直接作为 Vanna RAG 的 query, so that 检索对齐的是改写后的问题而不是口语原句。
34. As a 小模型, I want 分组和维度写进过滤这一项, so that 摘要保持四项、可控。
35. As a 小模型, I want 当前问题和摘要里都没有的时间、口径、过滤写成「未说明」或「无」, so that 我不编造条件。
36. As a Vanna RAG, I want 只用框架内已 train 的 DDL、文档/口径、问题-SQL 三路对照, so that 不必外挂第二套检索。
37. As a Vanna RAG, I want 只返回命中材料、不执行 SQL, so that 检索和查库分开。
38. As a 查库大模型, I want 一次查库对话只吃固定前缀、改写问题、这一次 RAG 命中材料, so that 我不会再检索第二遍。
39. As a 查库大模型, I want 只拥有只读查库工具, so that 我能按报错改 SQL 再跑，又不会变成第二个面对用户的规划者。
40. As a 查库大模型, I want 看见 SQL 报错或超时时在同一段查库对话里改 SQL 再调工具, so that 字段写错这类失败不必回到用户。
41. As a 查库大模型, I want 看见有行或 0 行时立刻停, so that 空结果不会被我当成还要再放宽条件。
42. As a 查库大模型, I want 新的 RAG 材料到来时从全新查库对话开始, so that 上一份 RAG 的报错和失败 SQL 不会污染这一次。
43. As a 查库大模型, I want 离开 B5 后这段对话被丢掉, so that 我没有跨轮记忆。
44. As a 查库大模型, I want 不能问用户、不能调小模型、不能再走 Vanna RAG、不能联网搜索, so that 对人说话、公开搜索和库内检索仍归主 Agent 和管线。
45. As a 程序, I want 用只读账号执行只读查库工具里的 SQL, so that 模型即使写出写语句也受账号限制。
46. As a 程序, I want 再挡一层禁写语句、表白名单、LIMIT、超时, so that 只读账号不是唯一防线。
47. As a 程序, I want 每次查库对话最多 5 次只读调用、单次超时 30 秒, so that 去掉计时器之后仍有保险丝。
48. As a 程序, I want 超时算一次工具失败并计入这 5 次, so that 扫全表不会靠换写法绕过上限。
49. As a 程序, I want 5 次用尽仍报错或超时则结束查库对话、两槽不动, so that 死循环不会覆盖上次成功底座。
50. As a 程序, I want 只在查库成功时成对覆盖上次 SQL 和查询摘要, so that 失败不会毁掉上一轮成功底座，也不会出现 SQL 新、摘要旧。
51. As a 程序, I want 0 行视为查库成功并覆盖两个槽, so that 下一轮续问可以依据这条空查询。
52. As a 程序, I want 工具失败用尽时扔掉本轮尚未落盘的摘要, so that 摘要不会单独写入。
53. As a 程序, I want 回填主 Agent 时有行给 SQL 和截断后的结果、0 行给没查到、失败给最后 SQL 和报错, so that 主 Agent 有材料对人说话。
54. As a 程序, I want 回填截断到最多 50 行或约 4000 字, so that 会话不被整包结果撑爆。
55. As a 程序, I want 不把整包查询结果、表结构塞进环 A, so that 闲聊上下文不被库结构撑爆。
56. As a 实现者, I want 调用 Vanna 时走「改写句 → 框架 retrieve → 把 context 交给查库对话」, so that 不会误用默认 generate_sql 再检索一次。
57. As a 实现者, I want 主 Agent 运行时默认只保留说话和查数工具, so that 默认的 bash、写文件不会绕开查数工作流，联网搜索也先不挂上。
57a. As a 实现者, I want 联网搜索按已定契约实现且开关默认关, so that 以后打开时不必再设计一遍。
58. As a 实现者, I want 训练材料三类都预先 train 进 Vanna, so that 只有 DDL、只有样例或只有口径时对照不会偏。
59. As a 安全负责人, I want 生产禁用管理员库账号, so that 泄露的是只读权限。
60. As a 维护者, I want 文档和实现都使用「主 Agent / 查数工具 / 小模型 / 查库大模型 / 当前问题 / 查询摘要 / 上次 SQL / 环 A / 环 B / 联网搜索 / 查库对话 / 只读查库工具 / Vanna RAG」, so that 以后的人不要用 DST、槽位、QueryContext 覆盖这套词。

## Implementation Decisions

- 没有现成代码仓库。本规格从零描述模块边界，不假设已有服务端。
- 模块划分：主 Agent（规划、对人说话、写出当前问题、会话记忆、调查数工具）；查数工具（封装环 B 工作流，默认挂载）；小模型（无记忆改写，产出改写问题 + 四项查询摘要）；Vanna RAG（三字段一次检索）；查库大模型（查库对话内生成 SQL 并只调只读查库工具）；程序（只读执行、次数与超时保险丝、按成功条件成对覆盖存储、编排 B3→B6）；联网搜索（已设计、默认不挂载）。
- 主 Agent 不写 SQL、不查库。要查数只调查数工具一次。查数工具内部 B3→B6 由程序编排，主 Agent 打乱不了，也不能把小模型 / Vanna RAG / 查库大模型拆成自己的多个工具。上次 SQL、查询摘要由工具内部从程序槽读取，不经主 Agent 传入。
- 一轮 = 一句用户输入。主 Agent 对这一句只规划一次：不调查数工具（环 A）或调查数工具一次（环 B）。需要先澄清再查数时，拆成两句用户话。联网搜索开启后，「先上网查公开说明再查库」同样拆成两句。同一句不又搜网页又调查数工具。见 ADR：一句用户话只规划一次。
- 主 Agent 按 ReAct 思考，可观察行为是每句是否调查数工具；查数工具内部是管线。B5 查库对话里多次只读跑 SQL 是工具内部小环，不是主 Agent 再调一次查数工具。
- 环 A 不得调查数工具，不得调用小模型、Vanna RAG、查库大模型；库里的精确数只来自查数工具回填；不得把表结构、SQL、整包查询结果塞进这一环。联网搜索默认关闭；开启前环 A 只说话。
- 主 Agent 记忆 = 运行时会话（用户原话、自己说过的话、查数工具回填；联网搜索开启后加上搜索回填）。不另做记忆模块，不做槽位状态机。上次 SQL 和查询摘要只放在程序槽，只给查数工具内部的小模型。
- 主 Agent 运行时（DeepSeek Harness）默认只保留「说话」和「查数工具」；bash / 写文件关掉。联网搜索按契约实现后默认不挂载。
- 查数工具契约：入参是当前问题；出参三选一（有行：SQL+截断结果；0 行：没查到；失败用尽：最后 SQL+报错）。查库成功时副作用为成对覆盖上次 SQL 和四项摘要。同一句最多调 1 次。
- 联网搜索契约：入参是一句搜索词；成功返回最多 5 条（标题、网址、摘要，单条摘要约 300 字）；失败返回错误原文，主 Agent 不编网页内容。开启后每一句环 A 最多 3 次调用，单次超时 15 秒并计入这 3 次。搜索回填只进主 Agent 会话，不写进上次 SQL / 查询摘要。网页数字不当成库里的数。
- 小模型输入契约固定为：固定前缀、上次 SQL（没有就空）、查询摘要（没有就空）、当前问题。不加近几轮对话。
- 当前问题由主 Agent 从用户原话整理而成，必须可独立理解。用户原话只进主 Agent。
- 小模型输出契约（来自已拍板的简单提示词，不是可执行 demo）：

```text
改写问题：<一句完整中文问句>
指标：<要算什么>
时间：<时间范围，没有则写未说明>
过滤：<条件或分组，没有则写无>
口径：<含税/未税等，没有则写未说明>
```

- 查询摘要就是上面四项。分组、维度算在过滤里。不写行数、报错、结果。由小模型在查库前产出，程序在查库成功时与上次 SQL 成对落盘。
- 改写句直接作为 Vanna RAG 的 query。三路材料：DDL、文档/口径、问题-SQL 样例。只检索，不执行 SQL。
- 查库大模型提示词：固定前缀（只读、不准编表、要 LIMIT）+ 改写问题 + 这一次 RAG 命中材料。禁止再检索第二遍。禁止其它工具。禁止问用户。
- SQL 执行：查库大模型调只读查库工具；程序用只读账号跑 SELECT；报错或超时返回给这段查库对话；有行或 0 行则离开 B5。
- 查库成功 = 只读执行未报错，包括 0 行。成功时程序成对覆盖上次 SQL 和本轮四项摘要。工具失败用尽：旧值不动，本轮摘要扔掉；回填主 Agent 的是最后 SQL 和报错。
- 没查到 = 查库成功且 0 行。对人如实说没查到；槽位仍覆盖；系统不再自动改条件再查。
- 保险丝：每段查库对话最多 5 次只读调用；单次超时 30 秒并计入这 5 次。这不是用来过期上次 SQL 的计时器。
- 离开 B5（成功、没查到、或次数用尽）即丢掉这次查库对话。新 RAG 材料到来也必须是全新查库对话。不清主 Agent 会话。
- 回填两路分开：给人说话的是截断结果 / 没查到 / 报错；给下一轮小模型的是程序槽里的上次 SQL + 四项摘要。
- 回填截断：最多 50 行或约 4000 字。
- 数据库：只读账号 + 程序护栏（禁写、表白名单、LIMIT、超时）。表白名单具体表未定。
- 训练：三类材料都要预先 train。本规格不规定具体 DDL/口径/样例文本，也不规定多业务是否拆训练空间。
- Vanna 按「train / retrieve / 把 context 交给查库对话」对接。禁止默认 generate_sql 全链造成二次检索。查库大模型可以是带只读工具的对话，但不是面对用户的第二套规划 Agent，也不是 Vanna 2.0 默认那套任意工具循环。
- 明确不准救活的方案：DST/槽位状态机；主 Agent 生成或执行 SQL；每轮用户说话就改写并缓存问句；用整包查库结果当改写上下文；把 RAG 写成增删改权限问题；给小模型加回近几轮对话；用计时器维持或过期上次 SQL；给查库大模型其它工具或联网搜索；0 行时系统自己再查一次；把联网搜索画成环 C；把 B3/B4/B5 拆成主 Agent 的多个工具。

## Testing Decisions

- 好的测试只断言一轮的外部行为，不断言提示词原文、向量库内部、模型权重、框架私有调用栈。
- **唯一测试缝：一轮。** 测试夹具注入前置状态（主 Agent 会话、上次 SQL、查询摘要），送入一句用户话，断言：给用户的回复、本轮查数工具调用次数、本轮联网搜索调用次数、工具入参是否为当前问题、工具回填、管线向外露出的改写问题 / 四项摘要 / RAG 材料 / SQL 文本 / 只读调用次数与每次返回、结束后上次 SQL 与查询摘要是否成对覆盖。环 A 用例断言查数工具次数为 0。**默认关闭时断言联网搜索次数为 0。** 同一句第二次调查数工具必须失败或被拒绝。
- 环 B 内部的查库对话、禁止二次检索、次数用尽后丢掉对话，也只通过这一缝观察：只读调用次数、每次工具返回（报错 / 超时 / 有行 / 0 行）、下一轮是否仍带着本轮查库对话、0 行是否覆盖了两个槽。不要为小模型、RAG、查库大模型、执行器再各开一条测试缝，除非一轮缝无法观察「有没有检索第二次」或「有没有第二次进入环 B」。
- 用测试替身替换小模型、Vanna RAG、查库大模型、数据库执行、联网搜索，避免测试依赖真实模型、真实库和真实外网。替身必须能模拟：有行成功、0 行、数据库报错、超时、改写问题、四项摘要、三路命中材料、搜索命中与搜索失败。
- 本仓库没有现成测试，没有可沿用的 prior art。

## Out of Scope

- 表白名单具体表、LIMIT 具体值。
- Vanna 训练语料的具体内容；多业务 / 多场景是否拆训练空间。
- Vanna 0.x 与 2.0 的版本选型（对接原则已定：检索一次、查库对话只调只读工具）。
- UI / 网页版裸 LLM；前端 React。
- DST、槽位状态机、主 Agent 写 SQL、外挂第二套 RAG、给查库大模型其它工具。
- 写库、管理库账号、用查询结果做自动改数。
- 现在就把联网搜索挂到运行中的主 Agent 上（契约已定，开启是后续工作）。
- 规划误判后的话术细则（该查却走环 A / 该聊却走环 B）；下一句用户话重新规划即可转过来，本规格不规定固定话术。
- 本规格不交付实现代码。
