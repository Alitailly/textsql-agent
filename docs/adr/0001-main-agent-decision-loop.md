# 主 Agent 是一个决策循环

主 Agent 按 ReAct 思考，并且**在一轮里循环**：思考 → 行动 → 观察 → 再思考，直到它认为材料够回答用户，才说话结束本轮。一轮里可以转好几圈，中途可以换工具；转几圈由程序兜底，不靠模型自觉。

它手里只有三个动作：

- **说话** —— 认为材料已经够回答。
- **调查数工具** —— 要库里的确切事实。一句用户话最多调 1 次。
- **联网搜索** —— 拿到库内容后，判断「光凭这些回复还不够 / 不对」，去补时效性内容。默认关闭。

三条边界：

1. **改写不归主 Agent。** 主 Agent 只写出「当前问题」交给查数工具；改写问题全部由工具内部的小模型（B3）产出。主 Agent 不参与改写。

2. **联网搜索不在环 B 内。** 它不封装进查数工具，也不是环 A 的专利——它是主 Agent 自己的一个动作，典型发生时机是「拿到查数回填之后」。库给不可幻觉的锚点，搜索给时效性，主 Agent 给合成。

3. **被拒的工具不打断整轮。** 查数工具用超了、或搜索熔断用尽，程序把那个工具从主 Agent 能看见的工具集里摘掉，循环继续，让它用手上已有的回填说话。始终没开口才兜底，并且兜底要打标记、别让用户对着空回复猜。

## 与旧说法的关系

本 ADR 原先记录的是「一句用户话只规划一次，只进环 A 或环 B 之一；同一句里不又搜网页又查库」。

**那个说法已作废。** 它把主 Agent 描述成一个一次性的二选一开关，既不符合设计意图，也与实现里已有的决策循环相抵触。作废的具体是三条：轮内只规划一次、环 A 与环 B 互斥、联网搜索只在环 A。

词和流程以仓库根目录 `CONTEXT.md`、`textsql-agent-flow.md` 为准。
